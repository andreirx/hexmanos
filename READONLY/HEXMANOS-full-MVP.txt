### Why this is superior
1.  **Immutability:** Once a version of an asset is written to S3, it is a file. It doesn't care about Postgres transaction limits.
2.  **Performance:** The Game Client will load assets directly from S3 (via CloudFront/CDN). The Game Server doesn't need to proxy the data bytes. This saves your M1 Max/AWS Compute bandwidth.
3.  **Resilience:** If the DB dies, you lose the *index* (who owns what), but the *assets* (the actual drawings and logic) are safe in the bucket.

*   **Decision:** Fixed `(x,y)` coordinates defined in the Map Editor.

*   **Reasoning:** Even in turn-based games, writing to disk (DB) on every packet (movement, cursor hover, lock request) creates unnecessary I/O latency. Since we are running on your M1 Max, memory is fast and abundant. The snapshot protects against a server crash losing more than 30s of progress.

**3. Asset Versioning: Option A (Immutable/Versioning)**

6.  **User** sees the rough 32x32 result on the grid and **manually fixes** the messy pixels.
    *   *Critical:* AI is the "Draftsman", User is the "Polisher". Do not trust raw AI output for final assets.

### 2. Technology Selection (32x32 & Sheets)

Generating a coherent *Animation Sprite Sheet* (Idle, Walk, Attack) in one prompt is currently **unreliable** for a generic MVP. It often results in hallucinated frames or misaligned grids.

**Recommendation for MVP:**
Generate **Single Keyframes** (e.g., "Idle Front"). The user creates the animation frames by modifying that base in the editor.

**Engine Options:**

**Option A: The "M1 Max Native" (Local Inference)**
*   **Tech:** Run **Stable Diffusion XL (SDXL)** or **Flux** locally using CoreML optimization (e.g., `DrawThings` app or a Python script with `diffusers`).
*   **Model:** Use a checkpoint trained on pixel art (e.g., **Pixel Art XL** or **Retro Diffusion**).
*   **Pros:** Free, infinite generations, private.
*   **Cons:** High engineering effort. You need to build a Python microservice to expose the model to your Java Spring Boot app (or call it via shell execution).
*   **Latency:** ~10-20 seconds per generation.

*   **Tech:** `DALL-E 3` or `Stability AI API`.
*   **Pros:** trivial implementation (REST call). Fast.
*   **Cons:** Costs money per click. DALL-E 3 refuses to generate true 32x32; it generates 1024x1024 which looks bad when downscaled unless prompted perfectly.

**The Winner:** **Option B (Stability AI)** for MVP.

  1. Creativity = Currency: Kids gain status by contributing quality assets to a global library
  2. Persistent Worlds: Private servers that persist over weeks (base building, resource accumulation, recruitment)
  3. Hybrid Play: Async solo base management + live turn-based tactical combat (XCOM-style)
  4. Sustainable Infrastructure: M1 Max runs compute (free), AWS handles truth (auth/storage/CDN)

  ---
  Short-Term MVP ("Walking Simulator")

  The Loop:
  1. User logs in (Cognito)
  2. User draws a 32x32 "Hero" and "Grass Tile" in browser (or generates via AI + polishes)
  3. User submits → Admin approves
  4. User creates Game Room with their assets
  5. User invites friend via URL
  6. Both see each other's custom avatars walking on custom tiles

  Success Metric: Full round-trip from "Pixel Drawn" → "Pixel Seen by Friend on different computer"

  No combat. No resources. No building. Just the creative pipeline + networked rendering.

  Critical Architecture Decisions (Locked In)
  ┌──────────────────┬───────────────────────────────┬────────────────────────────────────────────────────────┐
  │     Decision     │            Choice             │                          Why                           │
  ├──────────────────┼───────────────────────────────┼────────────────────────────────────────────────────────┤
  │ Storage          │ Pointer Pattern               │ DB = index, S3 = truth. Resilient, CDN-cacheable       │
  ├──────────────────┼───────────────────────────────┼────────────────────────────────────────────────────────┤
  │ Spawn Points     │ Fixed (x,y)                   │ Deterministic, tactical, debuggable                    │
  ├──────────────────┼───────────────────────────────┼────────────────────────────────────────────────────────┤
  │ Game State       │ In-memory + 30s snapshots     │ Fast writes, acceptable 30s data loss on crash         │
  ├──────────────────┼───────────────────────────────┼────────────────────────────────────────────────────────┤
  │ Asset Versioning │ Immutable                     │ v2 doesn't break games using v1                        │
  ├──────────────────┼───────────────────────────────┼────────────────────────────────────────────────────────┤
  │ Deletion         │ Soft (ARCHIVED)               │ Audit trail, recoverable                               │
  ├──────────────────┼───────────────────────────────┼────────────────────────────────────────────────────────┤
  │ AI Generation    │ Single keyframe + user polish │ Sheets are unreliable; AI = draftsman, user = polisher │
